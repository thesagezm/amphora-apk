# Amphora iOS → Android Port Plan

## Context

**Amphora** (`~/Amphora-ios`) is a mature, personal, unofficial Pandora client for iOS: native Swift/SwiftUI against Pandora's legacy JSON API v5, feature-complete to Pithos parity and at milestone M6 (379/379 core tests green; lyrics + translation, Last.fm scrobbling, radio-browser mode, themes, diagnostics all shipped). The goal is a **full-parity native Android port** living in this workspace (`/home/sagestation/code/Amphora-APK`, currently empty), built with **Kotlin + Jetpack Compose + Media3**, so you can install an APK on your phone instead of side-loading IPAs through LiveContainer.

Two facts make this port unusually tractable:
- **PandoraCore was designed as the port surface.** Its files repeatedly state "no UI, no AVFoundation — PandoraCore stays portable — pure logic for the Android port." It's 6,493 LOC of pure HTTP/JSON/crypto/byte-state-machine logic with 33 fixture-driven test files (379 tests) that port 1:1 to JVM JUnit as a correctness safety net.
- **This machine is already an Android dev box**: `~/android-sdk` (android-36, build-tools 36.0.0, platform-tools, emulator + google_apis system image, licenses accepted), JDK 17 at `~/tools/jdk-17.0.13+11`, plus Waydroid. Unlike iOS, every build and test runs **locally** — no fire-and-continue CI loop needed.

Per your working style (no subagents) all research and implementation happens directly in session, mirroring the iOS repo's `AGENTS.md`/`QUEUE.md` discipline (small units, one milestone at a time, `QUEUE.md` as working memory, no version bumps until you say otherwise).

## Stack mapping (iOS → Android)

| iOS | Android |
|---|---|
| Swift 6, async/await, actors | Kotlin 2.x, coroutines + StateFlow (Mutex/`Dispatchers` where Swift used actors) |
| SwiftUI, `@Observable` | Jetpack Compose, Material 3, dark-first |
| `PandoraCore` Swift package | `:core` Gradle module — **pure Kotlin, zero Android deps**, JVM JUnit tests |
| CryptoSwift Blowfish-ECB | **Built-in JCE** `Cipher "Blowfish/ECB/NoPadding"` — no third-party crypto dep |
| `URLSession` | OkHttp |
| `Codable`, `JSONValue`/`AnyJSON` | kotlinx.serialization (`JsonElement` for dynamic JSON) |
| `AVQueuePlayer` + `AVAudioSession` | Media3 ExoPlayer + `MediaSessionService` (background audio) |
| `MPNowPlayingInfoCenter` / `MPRemoteCommandCenter` | Media3 `MediaSession` (notification, lock-screen, headset/Bluetooth controls) |
| Keychain (`KeychainStore`) | Android Keystore AES-GCM wrapper (dependency-free) |
| Codable-to-disk prefs/history | kotlinx.serialization to files in `filesDir` (1:1 seam mirror) |
| `ArtworkCache` (bounded ImageIO decode) | Coil with size-constrained requests (bounded decode preserved) |
| `ArtworkColors` (pure palette math, already in core) | port verbatim — no androidx.palette needed |
| MD5 (Last.fm sigs), `Digest.md5` | `java.security.MessageDigest` (built in) |
| ICY probe over `URLSession` bytes | OkHttp streaming body + ported ICY byte state machine |
| CrashReporter → `last-crash.txt` | `Thread.setDefaultUncaughtExceptionHandler` → `filesDir/last-crash.txt` |
| ATS `NSAllowsArbitraryLoads` | `android:usesCleartextTraffic="true"` (plain-HTTP radio streams need it) |
| `UIBackgroundModes: audio` | foreground service type `mediaPlayback` |
| Haptics, TransportGlyph (drawn), matched-geometry player | Compose `HapticFeedback`, Canvas/Path port, shared-bounds transition |
| AirPlay route picker | system output switching; custom picker deferred to the last milestone (platform difference — Android routes audio via system UI) |
| Unsigned IPA via LiveContainer | signed debug/release APK, installed directly |

Identity stays fixed per iOS naming rules: display name **Amphora**, `applicationId` **`dev.personal.amphora`**, core module **PandoraCore**. Portrait-locked like iOS. minSdk **26** (Android 8), target/compile SDK 36.

```
  src/main/kotlin/…  # one file per iOS source file, same names
  src/test/kotlin/…  # ported fixture tests (MockTransport seam kept)
app/                 # :app — Compose UI, PlayerService, Media3, persistence
  src/main/AndroidManifest.xml
```

`PandoraAPI.swift` constants port verbatim (tuner.pandora.com endpoint, `android-generic` partner credentials, Blowfish keys `6#26FRL$ZWD` / `R=U!LH$O2B#`, additionalAudioURLs). Critical semantics to preserve exactly: zero-pad only a partial final 8-byte chunk (never a full extra block), hex lowercase wire form, `syncTime[4:14]` slicing, RFC 3986 strict query encoding (not `URLEncoder`), session-expiry 1001 → transparent re-login + replay-once.

## Milestones (one unit at a time, QUEUE.md updated per commit)

- **A0 — Skeleton.** Gradle project (version catalog, `:core` + `:app`), Compose `MainActivity` showing a placeholder, app icon (reuse `Tools/gen_appicon.py` output), manifest with cleartext + mediaPlayback permissions, `AGENTS.md` + `QUEUE.md`. Verify `./gradlew assembleDebug` green locally.
- **A1 — Core protocol port (the big one).** Port all 33 `PandoraCore` sources: `JSONValue`/`AnyJSON` → `JsonElement`, `PandoraCrypto` (JCE Blowfish + hex helpers), `URLBuilder`, `ResponseEnvelope`, `Errors`, `SessionManager`, `LegacyPandoraClient`, `Playlist`, `Feedback`, `Station`/`StationModes`/`StationOrder`, `MusicSearch`, `GenreStations`, `Advertisement`, `ArtworkURL`/`SongArtwork`/`ArtworkColors`, `HistoryStore`, `UserSettings`, `SleepTimer`, `LastFm`, `Lyrics`/`LyricsProvider`/`LyricsFallbacks`, `RadioBrowser`, `RadioStreamMetadata`, `NetworkDefaults`, `PandoraAPIClient` interface. Port the test suite alongside its source files — target all 379 green via `./gradlew :core:test`.
- **A2 — Auth.** Keystore-backed session store, `SessionManager` wiring, auto-login on launch, login screen + typed error display.
- **A3 — Stations.** Station list (artwork, explicit badge, quick-mix, reorder), create/rename/delete/search, genre stations, preferences store. `MainTabView` + `StationsView` + sheets.
- **A4 — Playback.** Media3 `MediaSessionService` wrapping ExoPlayer (queue = current + next for near-gapless prefetch, `onNeedMoreTracks` seam), media notification/lock screen, artwork cache (Coil, bounded), mini-player + full player with scrubber, background audio, interruption/route handling via ExoPlayer + audio focus.
- **A5 — Feedback, bookmarks, history.** Thumbs with reasons (`FeedbackBar`), sleep-song, bookmarks, Recents, sleep timer; skip-limit awareness.
- **A6 — Lyrics.** lrclib fetch + synced/plain rendering, Google-translate English translation (including the split-segment alignment fix), fallbacks, romanization → `LyricsPanel`.
- **A7 — Radio mode.** RadioBrowser client UI (`RadioView`, `BrowseStationsSheet`), favorites/recents/custom stations, ICY `RadioMetadataProbe` on OkHttp stream, live-lag scheduling so lyrics/artwork never lead the audio.
- **A8 — Last.fm + settings + diagnostics.** Scrobbler policy port (error 4/9 re-auth handling), Settings, Diagnostics (log tail + last-crash.txt), About, themes (`ThemeController`/`ArtworkThemeController`), crash handler.
- **A9 — Robustness & parity pass.** Session-expiry soak, offline/error states, accessibility (TalkBack labels, touch targets), output-switcher equivalents, device demo checklist mirroring the iOS Definition of Done: launch → auto-login → station list → tap → music plays ~2s → media notification metadata → thumbs → skip → survives backgrounding and session expiry.

AirPlay-style custom output picking (A9 tail) is the one feature Android makes awkward; it lands last or gets descoped with your say-so.

## Verification

1. **Unit tests**: `JAVA_HOME=~/tools/jdk-17.0.13+11 ./gradlew :core:test` — the ported 379-test suite is the protocol-correctness gate (fixture JSON comes straight from the iOS test files, no re-capture needed).
2. **Build**: `./gradlew :app:assembleDebug` each unit; APK lands in `app/build/outputs/apk/debug/`.
3. **Emulator smoke test**: the installed android-36 google_apis system image — install APK, walk login → stations → playback before handing anything to you.
4. **Your phone**: you install the APK; a milestone isn't done until you confirm it works, same rule as the iOS project.
5. Optional later unit: a GitHub Actions `android-build.yml` producing signed APK artifacts (I'll ask before adding workflows, per inherited convention).
